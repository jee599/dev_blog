사주 앱을 만들면서 처음 비용을 계산했을 때 숫자를 보고 멈췄다. 무료 분석 1건에 $0.085. 하루 1,000명이 오면 월 $2,550. 무료인데 돈이 나간다. 유료 전환율이 3%여도 유료 매출로 무료 비용을 못 메운다.

이건 사업이 아니라 기부다.

그래서 비용을 뜯어봤다. 3가지를 바꿨더니 88% 줄었다. 정확히는 시뮬레이션 기반 추정치다. 실제 프로덕션에서는 트래픽 패턴이나 캐시 히트율에 따라 달라지겠지만, 방향은 확실하다.

## 1. 프롬프트 캐싱 — 같은 교과서를 매번 다시 사지 마라

LLM API를 호출할 때마다 "시스템 프롬프트"를 보낸다. 사주 해석 가이드라인, 오행 설명, 응답 포맷 규칙 — 이게 매번 똑같은데 매번 새로 보내고 있었다. 대학교에서 매 수업마다 교과서를 새로 사는 꼴이다.

프롬프트 캐싱을 적용하면 이 시스템 프롬프트를 한 번만 보내고, 이후에는 캐시된 걸 재사용한다.

```
변하지 않는 것 (캐시): 사주 해석 가이드라인, 오행 규칙, 출력 포맷
변하는 것 (매번 새로): 유저의 생년월일 데이터, 엔진 계산 결과 JSON
```

비용 차이:

```
Claude cache_control: 캐시 히트 시 입력 비용 90% 절감
Gemini Context Caching: 캐시 히트 시 75% 절감
OpenAI prefix caching: 자동 적용, 50% 절감
```

우리 사주 프롬프트 기준으로 시스템 프롬프트가 약 2,000 토큰이고 유저별 사주 JSON이 300~500 토큰이다. 전체 입력의 약 80%가 매번 동일하니까, 캐시만 적용해도 입력 비용이 거의 1/5이 된다.

## 2. 모델 라우팅 — 모든 질문에 교수를 부르지 마라

처음엔 무료든 유료든 전부 Claude Sonnet으로 돌렸다. "어차피 좋은 모델이 좋은 결과를 내니까."

$4,500 vs $238. 같은 일. 같은 결과 품질. 19배 차이.

이게 모델 라우팅의 힘이다. 알바생이면 충분한 일에 교수를 부르면 시급이 100배다.

```
간단한 무료 요약 (3줄)     → Gemini Flash  ~$0.001/건
일반 유료 해석 (10섹션)    → Claude Sonnet  ~$0.02/건
심층 프리미엄 상담         → Claude Opus    ~$0.045/건
```

Gemini Flash $0.001의 근거: 시스템 프롬프트 1,500 토큰 + 사주 JSON 300 토큰 + 출력 200 토큰 = 약 2,000 토큰. Flash 단가(입력 $0.075/1M, 출력 $0.30/1M) 기준으로 건당 $0.0002~$0.001 범위. 캐싱까지 적용하면 더 내려간다.

근데 무료 분석은 사실 LLM이 별로 필요 없다. 엔진이 이미 오행 분포, 십성 관계를 정확하게 뽑아놓는다. 이걸 코드로 텍스트 포맷팅하면 LLM 비용 $0이다. 올해 운세 요약 한 줄만 경량 모델한테 시키면 된다.

무료 4섹션 구성:

```
성격 분석:   알고리즘 포맷팅     → $0
직업 적성:   알고리즘 포맷팅     → $0
올해 운세:   경량 모델 3줄 요약  → ~$0.001
종합 한줄평: 경량 모델 1줄      → ~$0.001
합계:       ~$0.002/건
```

$0.085에서 $0.002. 97% 절감. 유저 입장에서는 체감이 거의 없다. 어차피 무료 분석은 "맛보기"고, 진짜 깊은 해석은 유료에서 한다.

## 3. Structured Output — 불필요한 말을 제거하라

LLM은 수다쟁이다. "이제부터 분석을 시작하겠습니다. 먼저 오행을 살펴보면..."  같은 서두를 매번 붙인다. 이 서두도 토큰이고, 토큰은 돈이다. 게다가 출력 토큰은 입력 토큰보다 3~5배 비싸다.

JSON 스키마를 강제하면 이런 불필요한 문구가 사라진다. 프롬프트에 이런 식으로 넣는다:

```
다음 JSON 스키마에 맞춰서만 응답하세요. 설명이나 서두 없이 JSON만 반환하세요.

{
  "personality": "성격 분석 2~3문장",
  "career": "직업 적성 2~3문장",
  "yearly_fortune": "올해 운세 요약 1~2문장",
  "summary": "종합 한줄평"
}
```

이렇게 하면:

```
Before (자유 응답):
"안녕하세요! 분석 결과를 말씀드리겠습니다.
 당신의 사주를 살펴보면, 오행 중 목(木)의 기운이 강하게 나타나고 있습니다.
 이는 성장과 발전의 에너지를 의미하며, 특히 창의적인 분야에서..."
→ 약 200 토큰

After (스키마 강제):
{"personality": "목(木)의 기운이 강한 구조. 창의적이고...",
 "career": "기획, 콘텐츠, 교육 분야에 적성...",
 "yearly_fortune": "상반기 변화의 기운이...",
 "summary": "성장의 해. 새로운 시도에 유리한 구조."}
→ 약 80 토큰
```

출력 토큰 60% 절감. 출력이 입력보다 3~5배 비싸니까, 출력을 줄이는 게 비용 절감에 가장 직접적으로 먹힌다. 덤으로 프론트엔드에서 JSON 파싱만 하면 되니까 응답 처리도 깔끔해진다.

## 합산하면

세 가지를 독립적으로 추정한 뒤 조합한 시뮬레이션이다. 실제로는 캐시 히트율, 트래픽 패턴, 무료/유료 비율에 따라 달라지니까, 정확한 숫자라기보단 규모감을 보는 거다.

```
최적화 전 (전부 Sonnet, 캐싱 없음):  월 ~$3,316

적용 1 — 프롬프트 캐싱:        입력 비용 ~80% 절감
적용 2 — 모델 라우팅:          무료 티어 비용 ~97% 절감
적용 3 — Structured Output:   출력 토큰 ~60% 절감

세 가지 조합 시 추정:           월 ~$400 (약 88% 절감)
```

일일 1,000건 기준이고, 무료:유료 비율을 97:3으로 잡았다. 무료 건수가 압도적으로 많으니까 2번(모델 라우팅)의 효과가 가장 크고, 1번(캐싱)이 그 다음, 3번(Structured Output)은 유료 건에서 주로 효과가 난다.

사주 앱이 아니라 어떤 LLM 기반 서비스든 이 세 가지는 거의 그대로 적용할 수 있다. 핵심은 간단하다. 캐시할 수 있는 건 캐시하고, 싼 모델로 충분하면 싼 모델을 쓰고, 출력을 줄일 수 있으면 줄인다.

> "모든 질문에 교수를 부르지 마라. 알바생이면 충분한 일에 교수를 부르면 시급이 100배다."
